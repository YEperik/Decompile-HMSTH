# Verification and test strategy

## Local checks

Run from the repository root with Python 3.12 or newer:

```bash
python -m app --help
python -m app doctor
python -m unittest discover -s tests/unit -t . -v
python tools/check_public_release.py
```

The optional installed CLI can be checked with `python -m pip install .` followed by `ps2-workbench --help`. CI also builds a wheel, installs it into an isolated target directory, and smoke-tests the installed CLI.

## Test categories

The unit suite exercises workspace persistence and validation, synthetic ELF parsing, symbol/section inspection, relocation previews, draft history, input integrity, bounded process execution, Ghidra planning/export checks, and CLI behavior. Fixtures are generated by test code and are not copies of the commercial game.

A passing unit suite establishes only that those tests passed on that Python/OS environment. It does not establish:

- compatibility with every retail region/revision;
- correct interpretation of every PS2 instruction or data format;
- a successful full-game decompilation or binary match;
- compatibility with physical PS2 hardware;
- the existence of a playable PC build;
- legal permission to use any particular game file.

## Public-release hygiene

`tools/check_public_release.py` fails on common protected filename extensions, known console serial filenames, selected binary-content signatures (including ELF and common media formats), and archives that cannot be inspected safely. It checks archive member names, selected signatures inside archives, and nested ZIP/TAR content when the archive is supported by the Python standard library. CI runs it on each push and pull request.

This is intentionally a conservative heuristic check, not a complete copyright scanner. It can miss renamed, embedded, encrypted, unusual or encrypted archive payloads, and it can occasionally flag harmless files with generic extensions. Unsupported archive formats fail closed so they must be reviewed manually or removed. It is not a malware scanner, license scanner, or legal opinion. Maintainers must inspect the complete diff and all archives manually before publishing.

## Ghidra verification

Ghidra is optional. Install it separately from its official distribution and review its own license and requirements. The workbench checks declared installation/language assets, records hashes, and uses explicit workflows. A successful external process exit is not sufficient proof that export output is complete; inspect the generated result and verification report.

No third-party binary, language pack, JDK, BIOS, ISO, ELF dump, or extracted game asset should be added to this repository as a convenience download.
